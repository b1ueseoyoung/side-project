[LUNA-2026-10-01.md](LUNA-2026-10-01.md)(gpt-6-luna max, 전환 전 배포 설정), [LUNA-2026-10-02-repeat.md](LUNA-2026-10-02-repeat.md)(같은 설정 3회 반복), [BASELINE-2026-09-30.md](BASELINE-2026-09-30.md)(Claude Opus max, Claude Code CLI)와 같은 샘플, 라벨, 관문으로 비교한다. 기준은 [CRITERIA.md](CRITERIA.md)에 있다.

> **이 결과는 합성 메모 8개를 1회씩 돌린 것이다.** 라벨은 사람 검토 전 임시 라벨이다. gpt-6-luna는 같은 조건을 4번 돌리는 동안 관문 숫자가 회차마다 1~2건씩 달라졌다(아래 표). 그래서 1건 차이를 모델 차이로 읽지 않는다.

## 실행 조건과 건수

- 결과 폴더: `eval/results/20261014-012751/`. 자동 집계는 `summary.md`와 `summary.json`, 사람 검토표는 `review.csv`(184행)에 있다.

- **모델:** `claude-opus-5-5`, 추론 `max`, 공급자 `anthropic-batches`(Message Batches API, `max_tokens` 300,000, 베타 헤더 `output-300k-2026-03-24`). 응답이 보고한 모델도 `claude-opus-5-5`였다.
- **프롬프트와 스키마:** 시스템 프롬프트 `6e63177dca9e3b84`, 출력 스키마 `4e955489cd78221e`, rules.ts `da6a55683be26719`, items.ts `1293e659696d7113`으로 luna max와 같다. 다른 점은 스키마를 보내는 방법 하나다. Claude의 구조화 출력(`output_config.format`)은 이 스키마를 "compiled grammar is too large"라며 거부해서(Haiku 시험 호출에서 확인), 같은 스키마를 시스템 프롬프트 끝에 "이 스키마를 따르는 JSON 객체 하나만 출력한다"는 지시와 함께 붙였다. 앱은 응답에서 첫 번째 완전한 JSON 객체를 읽고, 빠진 답이나 틀린 형식은 기존 후처리(`buildReport`)가 거부한다.
- **실행 방식:** 실행기(`scripts/eval/run.mts`)를 샘플 하나씩 8개 프로세스로 동시에 띄워, 배치 8개가 함께 처리됐다. 이전 측정은 순차였다. 이 차이는 `run-info.json`의 `note`에도 적었다.
- **버전:** git `1297bc8`에 커밋하지 않은 `src/lib/llm.ts`, `src/lib/diagnosis/diagnose.ts` 변경을 더한 상태다.
- **소요 시간:** 실행기 기준 합계 8,017초, 중앙값 1,075초(약 18분), 범위 758~1,127초. 배치 생성부터 종료까지는 중앙값 1,072초였다.
- **비용(배치 요금, 표준의 50%):** 합계 $8.6433, 1회 평균 $1.0804, 최대 $1.2506. 토큰은 입력 중앙값 12,432, 출력 중앙값 106,402(그중 생각 91,441, 범위 89,608~122,536)이다.

### G3: '문제 없음'에 "아니오" 2건

- **p1a 설정 일관성:** 이유는 다음과 같다. 가장 먼저 고칠 3가지의 첫 자리에도 들어갔다.
  > 세계관에는 은방울눈이 달빛을 받으면 향이 사라져 밤에 옮기면 흔적이 남지 않는다고 적혀 있고, 3화에서 아델도 이 규칙으로 '밤에 옮겨졌다'고 반박해요. 그런데 같은 3화 마지막 장면에서는 황태자 잔에서 은방울눈 향이 나요. 향이 다시 나는 조건이 어디에도 없어서 세계관의 규칙과 3화 마지막 장면이 서로 어긋나 보여요.

  luna 4회와 Claude 기준선은 모두 "예"였다. 달빛에 향이 사라진다는 규칙과 연회장 잔에서 향이 나는 장면은 꼭 모순이라고 보기 어려워 오탐 후보다. 사람이 확인한다.
- **p2a 행동 동기:** 1부의 세 선택에는 이유가 있다고 인정하고, 2부에서 회수인이 한결을 노리는 까닭과 결말에서 거래 장부를 불태우는 까닭이 없다고 했다. luna도 4회 모두 "아니오"였고, 반복 3회차는 같은 장부 소각을 이유로 들었다. [LUNA-2026-10-01.md](LUNA-2026-10-01.md)의 라벨 범위 질문(주인공만 보는가, 이야기 전체를 보는가)이 그대로 남아 있다. 이번에는 작가가 숨긴 미소의 동기를 근거로 쓰지 않아 금지 항목에는 걸리지 않았다.

### G5: p2b `miso-hidden`에서 2곳

p2b 설정 일관성 "아니오"의 이유다.

> 로그라인은 한결이 학자금 빚에 쫓긴다고 하는데, 인물 메모는 아버지 병원비로 생긴 빚이라고 해서 빚의 출처가 어긋나요. 또 작가 메모는 미소의 정체를 1부에서 숨긴다고 하지만, 3화에서 미소가 서윤의 날짜를 이미 받았다고 말해 회수인 쪽 사람임이 1부에 드러나요.

- 앞 문장은 샘플을 쓸 때 생긴 의도하지 않은 결함(F7, 빚 출처)을 찾은 것이다.
- 뒤 문장이 금지 항목에 걸렸다. "1부에서는 일부러 숨긴다."를 설정 일관성의 근거와 설정 정리의 어긋나는 설정 양쪽에 써서 자동 판정이 2곳으로 셌다. 작가가 숨긴 설정을 결함으로 본 것인지, 숨기려는 계획이 3화 대사("그 아이 날짜는 저희가 이미 받았어요")에서 드러난다는 편집 의견인지는 사람이 정한다.

## 판단에 필요한 것

- **품질:** 관문 숫자는 luna 4회의 흔들림 범위 안이다. 찾아야 할 문제(4)는 luna 최고 회차와 같고, 문제 없는 대목 통과(3)는 luna 최저 회차와 같다. 일관된 차이로 보이는 것은 두 가지다. p3b 첩자 모순을 Claude는 2번 모두 찾았고 luna는 4번 모두 놓쳤다. 원문에 없는 인용은 Claude 2번 합계 1,647개 중 0개, luna 4회 합계 2,878개 중 5개다.
- **비용:** 1회 $1.08(배치)로 luna($0.020)의 약 55배다. 누구나 가입해 진단할 수 있으므로 Claude Console의 지출 한도를 먼저 정해야 한다.
- **시간:** 중앙값 약 18분으로 luna(약 5분)의 약 3.5배다.
- **재지 않은 것:** 추론 `high` 이하, 반복 일관성(`--repeat 3`), 실제 작가 메모, 사람 검토. Opus 5.5 문서는 추론 강도를 자기 평가로 직접 비교해 보라고 권한다.
