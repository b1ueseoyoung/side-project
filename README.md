# 투고 전 원고 진단

웹툰 기획서와 1~3화 대본을 넣으면 캐릭터, 상업성, 작법 세 축으로 진단하고 가장 먼저 고칠 점을 알려주는 개인용 도구.

- 진단 결과는 합격 확률 같은 숫자가 아니라 신호등과 근거(대본 인용)로 보여준다.
- 대사나 장면을 대신 써주지 않고, 문제와 방향만 짚는다.
- 좋은 점을 먼저 보여준다.

> 표시: ✅ 1주 프로토타입에 포함 · ⏳ 이후 단계

## 기능

### 1. 작품 정보 입력

한 화면에 모두 두지 않고 단계를 나눠 입력한다.

1. ✅ **장르** (필수, 목록에서 선택): 로판, 현판, 학원, 스릴러, BL 등
2. ✅ **로그라인**: 한두 문장. 입력란에 권장 분량과 예시를 보여준다
3. ✅ **시놉시스**: 전체 줄거리
4. ✅ **캐릭터**: 주요 인물 3~5명을 이름, 역할, 원하는 것으로 나눠 입력
5. ⏳ **선택 항목**: 목표 플랫폼·공모전(진단에는 쓰지 않고 기록만), 특히 봐줬으면 하는 부분
6. ⏳ **피드백 강도**: 순한맛, 매운맛. 같은 지적의 말투만 바뀐다

### 2. 대본 입력

- ✅ 1~3화를 화별 탭에 텍스트로 붙여넣는다. 프로토타입에서는 대본이 필수다.
- ✅ 입력란 옆에 대본 형식 예시를 둔다: `#장면 번호 / 장면 설명 / 인물: 대사`. 형식을 지키면 장면 단위로 근거를 짚을 수 있다.
- ✅ 글자 수를 실시간으로 보여준다.
- ⏳ 완성 원고 이미지 업로드 (컷 단위 근거, 스크롤 호흡, 말풍선 분석)

### 3. 진단

- ✅ 항목마다 예/아니오 질문에 답하게 하고, "예"에는 해당 대사나 장면 인용을 붙이게 한다. 신호등은 답을 보고 규칙으로 계산한다.
  - 질문이 모두 "예"면 초록, 일부만 "예"면 노랑, 모두 "아니오"면 빨강
- ✅ 판정 항목 9개

| 축 | 항목 |
| --- | --- |
| 캐릭터 | 욕망과 결핍, 행동 동기, 조연 구분 |
| 상업성 | 로그라인 훅, 연재 지속성 |
| 작법·연출 | 1화 도입, 3화 엔딩, 정보량, 대사량(설명조만) |

- 판정 불가: 첫 등장, 스크롤 호흡 (완성 원고 필요)
- ⏳ 차별점 (신호등 없이 참고 코멘트), 장르 적합성 (외부 데이터 확보 후)
- ✅ 진단 중에는 빈 로딩 대신 실제로 처리하고 있는 단계를 보여준다. 처리 방식과 다른 가짜 진행 표시는 쓰지 않는다.

### 4. 리포트

위에서 아래로 다음 순서로 보여준다.

1. ✅ **한 줄 총평**
2. ✅ **이런 점이 좋아요**: 스크롤 없이 보이는 위치
3. ✅ **가장 먼저 고칠 3가지**: 빨강 항목 우선. 카드마다 항목, 근거(몇 화, 어떤 장면이나 대사), 방향
4. ⏳ **요청한 부분에 대한 답**: "특히 봐줬으면 하는 부분"을 입력했을 때만
5. ✅ **항목별 신호등**: 축별로 접어두고, 펼치면 근거가 보인다. 판정 불가와 참고 항목은 끝에 따로 묶고 이유를 한 줄로 적는다

신호등은 색만으로 구분하지 않는다(WCAG 1.4.1).

| 상태 | 색 | 모양 | 글자 |
| --- | --- | --- | --- |
| 좋음 | 초록 | 동그라미 | 좋아요 |
| 보완 | 노랑 | 세모 | 조금 더 |
| 수정 필요 | 빨강 | 네모 | 고쳐요 |
| 판정 불가 | 회색 | 점선 동그라미 | 원고 필요 |
| 참고 | - | 없음 | 참고 |

질문이 하나뿐인 항목은 초록 아니면 빨강만 나온다. 프로토타입의 9개 항목 중 7개가 여기에 해당한다.

### 5. 원고 보기 ⏳

- 왼쪽에 대본, 오른쪽에 코멘트 패널. 코멘트는 짚은 문장과 같은 높이에 둔다.
- 대본에는 좋은 점과 고칠 점을 모양이 다른 밑줄로 표시한다.
- 코멘트와 "고칠 3가지" 카드마다 할 일 / 완료 / 동의 안 함 상태를 고른다.
- "이 대사로 바꾸세요" 같은 대신 쓰기 버튼은 두지 않는다.

### 6. 재진단 ⏳

판정 기준표와 일관성 목표치를 달성한 뒤에 연다. 같은 원고에 다른 판정이 나오면 비교 자체를 믿을 수 없기 때문이다.

- 좋아진 항목 수를 맨 위에 보여준다. 예) "3개 항목이 좋아졌어요"
- 항목별로 이전 → 지금을 나란히 두고, 좋아진 항목 → 그대로 → 나빠진 항목 순으로 정렬한다.
- 신호등이 바뀌는 짧은 전환 모션. 모션 줄이기 설정(`prefers-reduced-motion`)을 켜면 끈다.
- 수정한 부분을 표시하되, 어느 수정 때문에 항목이 바뀌었는지는 추정해 연결하지 않는다.

### 7. 모바일 ⏳

리포트를 다시 보는 용도로 설계한다. 요약은 세로로 쌓고, 원고 보기의 코멘트는 문장을 누르면 아래에서 올라온다. 긴 대본 입력은 PC를 권한다.

## 구조

- Next.js (App Router, TypeScript, Tailwind CSS)
- LLM: 로컬에 설치된 Claude Code를 `claude -p`로 호출한다 (`src/lib/llm.ts`). 본인 로그인으로 실행되므로 **본인만 로컬에서 쓴다.** 인터넷에 열거나 다른 사람이 쓰게 하지 않는다.

## 실행

Claude Code가 설치되어 있고 로그인된 상태여야 한다.

```bash
npm install
npm run dev
```

http://localhost:3000 에서 확인. 모델을 바꾸려면 `.env.local`에 `CLAUDE_MODEL`을 지정한다.
